## People and tenancy

Who a person is comes from directory, not from this app: Access proves the login,
`identity.Middleware` (after access) maps it to a directory person and refuses anyone without a grant
for this app. Data is keyed by `identity.From(ctx).ID` and every query filters by it (see the notes);
viewers read only. An adult may act for a kid profile (`X-Act-For: <kid id>`, only ids in
`Person.ActsFor`); `identity.ActorFrom` is who signed in. Onboarding: directory gets this app in
`callers` and its namespace in `networkPolicy.callerNamespaces`; the wrapper sets `directory.url`
and `directory.existingSecret` (key `directory-key`, the same value as directory's
`caller-__APP_NAME__-key`). Grant people in the directory UI. The local preview acts as a fixed
owner `local`.

## Structure

- Go: `cmd/__APP_NAME__/main.go` composes the routes (security headers, `/healthz`, public
  `/pwa/`, then Access for everything else). Thin handlers in `internal/api`, logic in domain
  packages, SQL only in `internal/store`, forward-only migrations in `migrations/`
  (`002_<name>.sql`, never edit an applied one). Each outside service behind one small interface.
- Migrations are additive: a release rolls (old and new pod overlap for seconds on the same
  database), so the old code must survive the new schema. Rename or drop a column in two releases.
- Frontend in `web/src`: `features/<x>/`, `lib/`, `components/` for shared primitives; imports point
  downward only. `web/src/foundation/` is registry-owned (`go tool frontend-registry check`); do
  not edit it, `sync` after an app-foundation bump and review the diff.
- General UI rules (shell, page titles, look, numbers): shared memory `ui`
  (`~/.agents/memory/ui.md`). App look here: palette, fonts, language.

## Known traps (from Color, Omni, Workbench)

- iOS zooms into inputs under 16px and stays zoomed: `foundation/touch.css` keeps fields at 16px
  and controls at 44px on touch; an app rule that goes smaller wins, and the phone audit reports it.
- Never autofocus a field on touch: the keyboard opens and the shell hides the nav.
- `no-pan-x` stays on `html`, `body` and the shell's `<main>`: without it a diagonal flick pans the
  page or swipes back in history.
- Every animation and moving transition sits under `@media (prefers-reduced-motion:
  no-preference)` (`foundation/motion.css` states the policy); overlays use `foundation/useSheet`,
  messages `toast()` from `foundation/toast`.
- View Transitions crash WebKit in Playwright's device emulation; animate page changes with CSS.
- `content-visibility: auto` on long lists shifts restored scroll positions; remember the item id
  and scroll to it instead.
- Status bar: `default` in `index.html`. `black-translucent` only with a dark top bar (white text).
- Only a real iPhone confirms the shell. Emulation: Playwright WebKit at 402×874.
- `public/sw.js` is the template's copy (replace it when app-foundation changes it); the app's own
  worker code (push, notifications, cache rules) goes in `public/sw-app.js`, which it loads.

## Local preview

```bash
cd web && pnpm install --frozen-lockfile && pnpm build && cd ..
AUTH_MODE=local go run ./cmd/__APP_NAME__        # backend + built UI on 127.0.0.1:__APP_PORT__
cd web && pnpm dev                               # Vite on 127.0.0.1:__VITE_PORT__, /api proxied
```

pnpm comes from npm at the version `web/package.json` names (`npm i -g pnpm@<version>`).
Checks (the Dockerfile runs the same): `go test ./...`, `go vet ./...`, `gofmt -l cmd internal`,
`cd web && pnpm typecheck && pnpm build`. Phone audit, before every UI change is pushed:
`cd web && pnpm build && pnpm test:phone` (built UI on 127.0.0.1:__PHONE_PORT__, API from the fixtures in
`e2e/phone.spec.ts`; add each new route there; a browser: `pnpm exec playwright install chromium`
or `CHROME=<chromium binary>`). Under Windows some Go tests fail on file locking; run
them in WSL or Docker.
